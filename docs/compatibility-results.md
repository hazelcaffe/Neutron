An initial UI check requires matching **visible** text. A login form or a working shell is not evidence of end-to-end app compatibility. The harness rechecks runtime state after interaction and records crashes and early exits.

## Reproduce

```sh
pnpm compat:fetch
pnpm build
pnpm compat:sweep
# Targeted, with IPC/lifecycle diagnostics:
pnpm compat:sweep joplin vesktop --trace
# Exercise real file persistence and a real request/response:
NEUTRON_OBSIDIAN_RESOURCES=/path/to/obsidian/resources \
NEUTRON_JOPLIN_RESOURCES=/path/to/joplin/resources \
NEUTRON_DRAWIO_RESOURCES=/path/to/drawio/resources \
NEUTRON_POSTMAN_RESOURCES=/path/to/postman/resources \
NEUTRON_VESKTOP_RESOURCES=/path/to/vesktop/resources pnpm test:e2e
```

Installers are extracted, never launched. App interaction probes belong in tests and the sweep harness. The runtime does not patch the imported vendor files. The sweep uses a separate persistent profile per app; `--fresh` replaces only that sweep-owned profile. `NEUTRON_START_TIMEOUT` sets the startup deadline, and `NEUTRON_SWEEP_WAIT` extends observation. The dev-only asset-rebuild regression runs separately with `NEUTRON_TEST_DEV=1`.

## Runtime coverage behind the results

- **Browser handoff:** `tests/e2e/browser-login.spec.ts` verifies the official Figma and GitHub Desktop buttons with a fresh profile (`tests/browser-login.playwright.config.ts`). `external-auth.spec.ts` exercises registered scheme callbacks, including query/fragment preservation. `loopback-auth.spec.ts` verifies the virtual loopback HTTP listener with a real redirect and response. `two-step-transport.spec.ts` checks opaque tickets, leading-zero strings, cookie rotation and `fetch` credentials modes using a local fixture. None of these requires personal credentials.
- **Git and fonts:** `node tests/compat/git-desktop.mjs` drives the official GitHub Desktop through the Git workflows above against `git-server-fixture.ts`; `.cache/lane-github-desktop/evidence/desktop-uBRVZ8/result.json` records its latest nine-step run. Undo, stash, conflict resolution and the github.com clone were driven interactively; their screenshots are in `.cache/lane-github-desktop/run1`–`run6`. `node tests/compat/desktop-signin.mjs` checks the browser sign-in round trip without an account (`.cache/lane-github-desktop/evidence/desktop-signin-kSeV82/`). `packages/runtime/tests/git-workflows.test.ts` covers the command shapes Desktop parses, smart-HTTP transfers, LFS and line staging. `.cache/compat-apps/code-font-perf/evidence/integrated-auth-final/report.json` records the integrated VS Code trace: Seti WOFF and Codicon TTF returned HTTP 200 and matched the package hashes; a later keystroke reached the editor in 33 ms in that run. The corresponding `evidence/README.md` describes the matched performance trials.

- IPC is dispatched to the sending frame, its web contents and the main IPC object. Delayed `sendSync` replies, renderer console events, isolated/shared preload exports, strict script declarations and window handoff have browser regressions.
- Node HTTP request/response streams, Node/Web stream adapters, Brotli and Zstandard have contract tests. Sync XHR over a proxied virtual URL, HTTP(S) protocol handlers scoped to separate sessions, and classic/module worker imports are tested with neutral app fixtures.
- Standard SQLite files use sql.js in main, child and renderer contexts. SQLCipher 4 uses SQLite3 Multiple Ciphers WASM. Its differential test can use `NEUTRON_SIGNAL_SQLCIPHER_ADDON` to check native/portable database interchange. Legacy cipher migration, general cross-process locking and native SQLite extensions are unsupported.
- File data and update times replicate between execution contexts. Browser file requests wait for writes already queued for that app in the service worker. A fixture exercises first load, overwrite, and deletion with competing log writes. Bounded OPFS reads and writes and shared immutable resource buffers reduce the cost of large imports. Abrupt page termination can interrupt pending writes.
- Browser workers execute JavaScript workers/forks and utility processes. Arbitrary native `.node` libraries, OS executables and hardware-backed services remain major compatibility boundaries. Permissive stub warnings are retained in the evidence.

## Products without an acquired runnable Electron distribution

The current Teams Windows client uses WebView2; the historical Linux Electron download returned 404.
